# OSR6 联动

通过 TCode 协议驱动 OSR6 / SR6 等外设（WiFi UDP、USB 或传统蓝牙串口），并支持把 funscript 时间轴播到某个轴上。

## 目录结构

```
extension.json      扩展清单（entry = dist/index.mjs，studioEntry = dist/studio.js）
ui/                 引擎托管的界面文档（设置页 + 4 个输入对话框）
src/
  index.tsx        扩展入口：项目设置 + 全部剧本方法
  studio.tsx       编辑器设置页：funscript → WAV 载波导入
  tcode.ts         TCode 编码（轴表、幅值、DSTOP）
  transport.ts     传输层：UDP / USB / 传统蓝牙 SPP、设备授权与写入队列
  serial-device-picker.tsx  玩家串口选择与授权面板
  serial-probe.ts  编辑器串口身份测试与资源释放
  udp-probe.ts     编辑器 UDP 试动、取消与资源释放
  native-serial.ts   serialport 桌面系统串口适配（Windows / macOS / Linux）
  serialport-loader.ts  内嵌原生驱动校验、解压与按需加载
  runtime-state.ts  按运行周期隔离设备与脚本状态
  engine.ts        设备引擎：目标值、平滑、固定频率下发、急停
  funscript.ts     funscript 解析与采样（纯函数）
  player.ts        播放时钟：play/pause/resume/seek/stop、循环、倍速
  script-store.ts  指针解析（asset / var / global / 内联）+ 素材缓存
  carrier.ts       WAV 载波编解码（LGF1 + CRC32）
tools/
  pack-funscript.mjs  CLI：把 .funscript 打包成 WAV 载波
  carrier.mjs         由 carrier.ts 打包生成（npm run pack:build）
scripts/watch.mjs     两趟构建的 watch 模式
scripts/serialport-bundle.mjs  将 serialport 和各平台驱动打入单文件入口
```

## 设备

| 通道 | 桌面版 | 网页版 |
|---|---|---|
| WiFi / UDP | 用宿主的 Node UDP 能力直连 | 本版不能直连；需要另行实现本机桥接或设备 WebSocket |
| USB 串口 | Web Serial 或 serialport 原生系统串口 | 支持 Web Serial 的安全页面可用 |
| 传统蓝牙串口 SPP / RFCOMM | 先配对并由系统提供串口；Web Serial 或 serialport | 支持蓝牙串口的浏览器中可用 |
| BLE | 本版未实现 | 本版未实现 |

USB 指的是被系统识别为串口的连接，不包含 HID 或私有 USB 协议。传统蓝牙和 BLE
是不同通道；设备自身必须提供 SPP / RFCOMM 服务才能用本版的蓝牙串口功能。

### 玩家连接步骤

1. 在扩展自带设置界面点击「用串口」，或在剧本中调用新增的「选择串口设备」。
2. 在弹出的面板选择「USB」「蓝牙串口 SPP」或「自动识别」，填写设备固件使用的波特率。
3. 蓝牙设备先在系统设置中配对；点击「选择 / 授权新设备…」，在宿主选择框中选设备。
   已授权设备也可以直接从列表选择。
4. 看到「已连接」后点击「关闭」继续游戏。连接本身不触发运动；
   主动调用「测试设备连接」才会试动。面板还提供急停与断开。

浏览器通道的自动连接不会弹授权窗口；只有一个匹配且可用的已授权串口时才会尝试连接。
多个候选、原设备被移除或授权失效时要求重新选择，不回退到第一个端口。
端口对象只保留在当前运行周期内，不写进存档。序号和 VID/PID 不能唯一识别同型号设备。

网页版首期以桌面 Chrome / Edge 为验收目标，页面需使用 HTTPS 或 localhost。
嵌入游戏的 iframe / Permissions Policy 也必须允许 serial。Studio 和桌面发行版
需要宿主实现串口选择和设备授权；仅存在 navigator.serial 不代表宿主已实现选择窗口。
本扩展不会修改宿主进程或替用户授予设备权限。

### Studio 没有弹出串口选择窗口时

Electron 宿主未接入选择界面时，添加串口可能立即返回“没有选择设备”，即使系统已经识别出 COM 口。
此时可使用本扩展的桌面原生串口通道，无需修改 Studio 安装文件：

1. 在 Studio 扩展设置中，将「串口访问方式」切到「桌面原生串口」。旧 `windows` 设置会自动按原生通道读取。
2. 当前设置页会列出系统串口（Windows 为 COM，macOS / Linux 为设备路径）；未显示时点击「刷新系统串口」。
3. 在串口下拉框中明确选择设备，「测试设备」按钮随即启用。波特率需与固件一致。
4. 点「测试设备（小幅试动）」会查询身份，再让 L0 轴按 50% → 60% → 50% 缓动，最后发送停止指令并释放端口。每段缓动 600ms，动作部分约 2.3 秒。
5. 游戏运行时仍可调用「选择串口设备」或在自带设置页点「用串口」，在面板中选择设备后连接。

原生通道使用锁定版本的 `serialport 13.0.0`，直接通过它的 Node-API 驱动读写端口，已经移除 PowerShell 桥接。
游戏入口通过 SDK 加载固定名称的 Node 内置模块；编辑器没有 ExtensionContext，按本地设备调试需求使用宿主 Node。
它需要 Node 20+ 的桌面宿主；编辑期原生访问仍属于特权入口，不能假定工坊宿主允许。

构建将 npm 代码和官方包内的 `.node` 预编译驱动压缩内嵌到两个 JS 入口，保留原有宿主共享依赖配置。
首次使用原生通道时，按平台、架构和 Linux libc 选择驱动，校验 SHA-256 后写入用户临时目录中的独立 `osr6-serialport-*` 文件夹并加载。
不需要源码目录、外置 node_modules、玩家安装 Node/npm 或运行时下载。Unix 加载后立即清理临时文件；Windows 锁定的文件在宿主退出时尝试清理，仍被锁定的交由系统临时文件清理。
相同入口复用驱动构造器，但端口与连接按预览/编辑器会话隔离；切换页面、取消测试和退出预览会释放端口。

包内覆盖 Windows x64 / x86 / ARM64、macOS Intel / Apple Silicon，以及 Linux x64 / ARM64 / ARM 的对应预编译驱动。
Linux 枚举沿用 serialport 的 `udevadm`，需要系统提供该命令和串口访问权限。其他平台/架构会显示明确错误。
跨平台路径和驱动选择有自动检查；macOS / Linux 的实体设备仍需在各平台验收。安卓原生桥接和 BLE 不在本次实现范围。

原生通道始终要求手动选择设备，即使系统只有一个端口也不自动连接。
蓝牙必须在系统配对并提供可枚举的串口；本扩展不负责创建蓝牙映射。网页版继续使用「浏览器授权」。

参考：[Web Serial](https://developer.chrome.com/docs/capabilities/serial)、
[传统蓝牙串口](https://developer.chrome.com/blog/serial-over-bluetooth/)、
[Electron 设备授权](https://www.electronjs.org/docs/latest/tutorial/devices)。

## 指针（仅供内部解析用）

正式流程是「素材 + 播放脚本」，用户不需要接触指针。指针只保留给内部的
`解析 funscript`（隐藏方法，不进 Studio 的方法选择器）：

| 指针写法 | 含义 |
|---|---|
| `asset:se/xxx.wav` | **正式来源**：读项目素材里的 WAV 载波（见下一节） |
| `var:变量名` | 从项目变量读取。变量值可以是 JSON 文本，也可以是已解析的对象 |
| `global:键名` | 从 `globalThis.__osr6Scripts` 读取（普通对象或 Map） |
| `{` / `[` 开头 | 直接当作内联 JSON 解析（测试、短脚本） |
| 其他裸名字 | 兜底再去 `globalThis.__osr6Scripts` 找一次 |

外部加载代码只需要做一件事：

```js
globalThis.__osr6Scripts = globalThis.__osr6Scripts || {};
globalThis.__osr6Scripts.fight01 = funscriptJsonText;
```

变量与全局表由各自的持有者负责生命周期；扩展侧不再维护内存登记表。

## WAV 载波（funscript 的正式存放方式）

Studio 的素材管线**不接受 `.funscript`**：11 个资产分类都不含这个类型，改名成
`.json` 会被白名单拒绝，`assets/dynamic/` 只接受真正的 Spine/Live2D 模型。
但 Studio 接受 `assets/se/*.wav`，并且导入是**逐字节原样拷贝**（实测 SHA-256 不变）。

所以 funscript 被打包进一个 8-bit PCM 的 WAV：`data` 块里是带校验的原文。
运行时扩展 `fetch` 这个素材、跳过 WAV 头、校验 CRC、解出文本再播放。

### 打包

```bash
npm run pack -- "D:/脚本/fight01.funscript"          # 同目录生成 fight01.wav
npm run pack -- "D:/脚本/fight01.funscript" out.wav  # 指定输出
```

工具会先校验 JSON 和 actions，再打包、立刻解一遍自检（内容和原文不一致就报错）。

### 在 Studio 里使用

1. 把生成的 `.wav` 导入 `assets/se/`
2. 选中它，把打包策略改成**强制打包** —— 未被引用的素材默认 `willPack: false`，
   不设这一步，开发时正常、打包后素材会消失
3. 剧本里用 `播放脚本` 选中它（脚本组的一行 = 轴 + 素材 + 强度范围）

### 载体格式

```
WAV: RIFF/WAVE, PCM 8-bit, 单声道, 44100Hz
data 块：
  0   4  魔数 "LGF1"
  4   1  版本（当前 1）
  5   1  标志，保留
  6   4  payload 字节数（uint32 LE）
  10  4  payload 的 CRC32（uint32 LE）
  14  N  UTF-8 的 funscript JSON
```

解析按块遍历（不假设 44 字节头），CRC 不匹配时报「文件在打包后被改动过」。
100 KB 的脚本约等于 2.3 秒的 8-bit 单声道音频，对素材管线没有负担。

## 编辑器设置页：一键导入 funscript

Studio 支持扩展自带编辑器页面（`studioEntry` + `@avg-studio/studio-ui`），这里用它做了
「选 .funscript → 打包成 WAV → 写进项目 assets/」的按钮，省掉手动跑 `npm run pack`。

页面行为：

1. 点「选择 .funscript」，选中后显示动作点数、时长、生成的 WAV 大小
2. 点「打包并写入资产目录」，写到 `<项目目录>/assets/<输出目录>/<名字>.wav`
3. 输出目录由设置 `osr6.scriptImportFolder` 决定（默认 `bgm`），
   同名文件默认自动加 `-2`、`-3`，可用 `osr6.scriptImportOverwrite` 改成覆盖

写完仍需要在 Studio 里**刷新资产**（Studio 不会自动扫描新文件），并把该素材的
打包策略设为**强制打包**，否则不会进构建。

### 设备面板：配置与短暂测试

「连接方式」保留原有 udp / serial 数据格式，串口内新增「自动识别 / USB / 传统蓝牙 SPP」。
蓝牙模式忽略 USB VID/PID；USB 与自动模式按配置过滤。列表显示的是完整授权列表的序号，
筛选之后不会重新编号。

- 「添加串口…」由真实按钮点击直接触发设备选择，授权后选中该端口。
- 若 Studio 点击后没有出现选择窗口，可切到「桌面原生串口」；当前设置页会显示系统串口下拉框，选中后可直接测试。
- 「刷新」只枚举当前窗口已授权的设备。
- 点列表中的端口可选择本次要测试的设备。多设备时不能只凭旧序号猜设备。
- 切换设备或连接参数后，状态恢复为「未测试」，不会沿用上一个设备的身份和结果。
- UDP 测试保留小幅试动；串口测试查询 D0 身份后，L0 轴缓慢回到中位 50%、移动至 60%、再回到 50%，最后发送 DSTOP 并释放端口。
- 串口测试每段先等待实际写入，再给设备足够时间完成缓动，不会把回中与停止同时发出。测试期间可点击「停止测试」，中止后不再发送后续位置。
- UDP 同样支持「停止测试」；停止或离开设置页会立即取消后续位置定时器，尝试发送 DSTOP 后关闭连接。
- 串口固件不回身份信息时仍会试动，并显示「端口已打开、没有身份回复」，不会仅据此认定连接失败。界面只报告指令已发送，实际动作需观察设备确认。
- 成功、超时、取消或离开设置页都会清理读取锁、写入锁和端口。
- 原生串口测试使用 serialport；离开设置页或切换连接通道时销毁串口会话。
- 中止或离开页面时先尝试发送停止并释放端口；设备断线时停止指令可能无法送达，错误会保留。
- 测试期间请先断开预览里的设备，避免端口被占用。

编辑器和玩家窗口的授权不保证共享，发行游戏后仍需要玩家自行授权。
设备连接、写入错误和窗口能力不足会分别显示；不会用「改用 UDP」掩盖网页版没有 UDP 的情况。

### 实现说明（重要取舍）

- 项目目录来自宿主注入的 `globalThis.__avgVisualUIProjectDir__`，实测就是工程根目录。
- 写文件用的是宿主窗口里的 Node `require("fs")`。**官方文档不建议在编辑期入口用
  Node**：工坊审核会因此把扩展标记为特权、需要人工过审。这是本地扩展的取舍——
  编辑器页面没有「导入素材」的接口，不碰 `fs` 就无法把转换结果放进资产目录。
- 编辑期入口 `src/studio.tsx` 只给 Studio 加载，游戏运行时不加载它。

## 玩家侧：扩展自带的设置界面

玩家的地址、端口等设置继续使用原有界面文档；新增的串口选择面板由独立隐藏模块渲染，
提供设备列表与真实点击授权，不重做原有可视化界面。

### 界面文档

`ui/` 目录下的界面文档会注册成扩展界面：

| 文档 | 说明 |
|---|---|
| `ui/osr6-settings.json` → `@com.httdesu.osr6-bridge/osr6-settings` | 唯一界面：内嵌地址输入对话框（写项目变量 `OSR6设备地址`）+ 连接方式按钮 + 测试 / 关闭 |

界面结构：顶部两个模式按钮（用 UDP / 用串口）直接调用 `设置连接方式`；串口模式会打开设备选择面板。方法写变量后
面板按 `OSR6连接方式` 显隐；每行数值后面有一个 ✎ 图标，点开对应输入对话框。
没有"启用连接"按钮——停在哪个面板就用哪种连接方式。
也可以从任意 UI 按钮用 `ui.open` 指向 `osr6-settings`。

界面采用深色主题（背景 `#0b1219`、青色强调 `#5fbbae`/`#7fd4c8`），和引擎原生的输入对话框统一色调：
卡片里是三行只读值（连接方式 / 设备地址 / 设备端口），右侧两个按钮打开独立的输入对话框。

四个输入对话框（地址 / 端口 / 串口序号 / 波特率）**全部使用 string 类型**，因此外观完全一致；
对应的项目变量也都是字符串，扩展侧用 `toNumber()` 解析，非法值回落到作者的扩展设置。

### 存储与自动重连

- 保留玩家变量 OSR6连接方式（udp / serial）、OSR6设备地址、OSR6设备端口、
  OSR6串口序号、OSR6波特率；新增 OSR6串口类型（auto / usb / bluetooth）和
  OSR6串口访问方式（web / native，旧 windows 值自动兼容）。
- 读取优先级为玩家变量 → 作者扩展设置。多个设备时必须选择真实端口，序号仅兼容旧配置。
- 每 2 秒检查连接参数；参数变化后停止播放并重连，包含波特率和串口类型变化。
  手动连接会同步本次参数，避免随后轮询再重复重连。
- 预览、主游戏按 SDK 的运行周期隔离。退出预览会停止播放、取消测试定时器、
  关闭端口；尚在打开中的连接完成后也会立即关闭。
- 异步写入失败或设备断开会更新连接状态并停止播放。重新连接需要明确操作或配置变化，
  不会在后台反复弹窗。
- 串口每次只提交一条写入，慢链路会合并等待中的各轴最新位置。急停丢弃尚未发送的位置，
  已提交给驱动的写入无法撤回。
- 急停、停止脚本、断开、重连或退出预览也会取消正在加载的脚本；较早的加载完成后不会重新启动播放。
  开始新脚本会取消此前设备测试的延迟动作，避免混入脚本输出。
- 已配置但禁用的轴不会发送位置指令；只有轴配置完全为空时才使用默认轴。

## 播放脚本

播放接口是**组**的形式：一次调用可以同时驱动多个轴，每个轴一条脚本；
只有一条脚本时就传长度 1 的数组。

- 组内每个轴一个独立的播放器，同时开播，共享开始时刻
- 同一个轴在一次调用里出现两次会报错（请合并成一条）
- `暂停脚本` / `继续脚本` / `跳转脚本` / `停止脚本` / `读取脚本播放状态` 都作用于整组
- 倍速不在播放参数里：用 `设置播放速度` 单独调，播放中立即生效且不跳进度，没在播放时记下来给下次用

素材仍然是 WAV 载波（见上一节）。每一行只有两个参数：

| 参数 | 说明 |
|---|---|
| 轴 | 这一行驱动哪个轴（L0–A2） |
| 脚本素材 | WAV 载波（audio 素材） |

强度不在播放参数里，由 `设置强度范围` 单独设置（同样是列表输入，按轴生效）：

| 参数 | 范围 | 默认 |
|---|---|---|
| 轴 | L0–A2 | L0 |
| 强度下限（%） | 0–100 | 0 |
| 强度上限（%） | 0–100 | 100 |

输出按 `下限 + (上限 - 下限) × 脚本值` 线性重映射，播放中改会立即生效。

恒定位置片段同样立即更新；暂停时只保存新的范围，继续播放时应用，不会因调范围而自行恢复运动。例如：

- `0–100`：原样播放
- `0–40`：整体压到四成幅度（浅一些）
- `40–100`：把整段抬到 40%–100%（只在上半区活动）
- `100–0`：反向（等价于「输出反相」）
- 上下限相同：整段保持恒定强度

## Studio 与发行版人工验收

自动检查使用模拟设备，不代表已经验证实体硬件或宿主授权窗口。
另有使用内嵌原生驱动的只读系统串口枚举检查，不会打开端口或发送运动指令。

1. 在 Studio 扩展设置中选「USB / 蓝牙串口」→「桌面原生串口」→「刷新系统串口」；
   选中设备后点击「测试设备（小幅试动）」，预期 L0 50% → 60% → 50%，完成后释放端口。旧 windows 配置应显示为桌面原生串口。
2. 运行预览，在自带设备设置中点「用串口」，或者调用「选择串口设备」；
   授权连接、关闭面板后调用「测试设备连接」，预期 L0 中位 → 68% → 中位。
3. 调用「急停」后不再继续运动；退出预览再重新进入，应能重新连接同一端口。
   在脚本素材尚未加载完时急停，加载完成后也不能自行恢复；设备测试途中启动脚本，不应再混入测试动作。
4. 拔下 USB 或断开蓝牙，应显示未连接与错误。重新插入后手动选择并连接，
   不能继续把旧连接显示为已连接。
5. 在系统里配对提供 SPP 的蓝牙设备，面板切「蓝牙串口 SPP」后选择、连接、试动。
   若设备只提供 BLE，本版不能连接。
6. 使用两个候选端口验证：自动连接要求选择设备，筛选或列表顺序变化后不能误连第一个。
   测试一个端口后选择另一个，状态应恢复为「未测试」。UDP 测试中停止或离开设置页，不应继续发送后续位置。
7. 导出网页，在 HTTPS 或 localhost 的支持浏览器中重复 USB / 蓝牙流程；
   首次授权必须由按钮触发，串口过程不应出现 Node 模块错误。
8. Windows、macOS、Linux 的 Studio/桌面发行版分别验收 USB 和系统蓝牙串口，包括脱离源码目录的发行包。
   原生方式需要宿主允许 Node；浏览器方式需要宿主选择框和权限。普通网页的 WiFi UDP 仍不属于本版直连范围。
